# v0.4.0 — Trustworthy CI

Release date: 2026-11-18

## Summary

A green CI run now means that the code passes the lint, format, type and
security checks. The authentication debug log no longer shows secrets.

## Issues Resolved

- [#17](https://github.com/unibrain1/Fireboard/issues/17) — fix: CI lint and security steps never fail (|| true) (PR #28)
  - CI has a mypy step. The bandit and vulture steps fail the build when
    they find a problem (`|| true` is removed).
  - The code passes mypy: the cookie jar is typed as `AbstractCookieJar`,
    `_channel_number` is an `int` on the channel sensors, and the
    `domain=` class keyword on `ConfigFlow` has one `type: ignore`.
  - The authentication debug log shows only the cookie names and whether
    a CSRF token was found. It does not show cookie values or the token.
    A new test checks that the log holds no secrets.

## Other changes

- CI runs on pushes to `main` and `milestone/**`. The old trigger named a
  `develop` branch that does not exist.
- The version is 0.4.0, and `README.md` has a v0.4.0 Changelog entry.

## Accepted risks

- `main` has no branch protection, so a red CI run does not block a merge
  or a release (#33).
- `hassfest` uses `@master`, not a commit SHA (#32).
- The mypy configuration is permissive. It checks only annotated code (#34).
- CLAUDE.md "Tests" does not list the CI gates (#31).

## Deployment

1. In Home Assistant: Settings → Updates → FireBoard → Update.
2. Restart Home Assistant.

No new configuration, requirement or entity change.

## Verification

- HACS shows version 0.4.0.
- The FireBoard sensors show temperatures after the restart.
